# Apps Script для сайту бібліотеки

Ця папка містить два канали роботи з тією самою службовою Google-таблицею:

- `PublicCatalogApi.gs` — публічний `doGet` з безпечним набором даних для каталогу вчителів;
- `LibrarianGateway.gs` — захищений `doPost` для службових довідників і подвійно заблокованого застосування перевіреної чернетки.

Публічний канал є лише читанням. Локальний маніфест містить точний OAuth scope `spreadsheets`, бо підготовлений шлюз у майбутньому має записати один перевірений тип операції. Запис неможливий, доки `LIBRARIAN_WRITES_ENABLED=false` хоча б в одному з двох місць: у Sites або Script Properties. Поточне продуктивне розгортання v3 лишається read-only; новий код застосування до нього не розгорнуто.

## Що повертає публічний API

Публічний канал повертає бібліографічні дані, обкладинки та доступні залишки. Він не повинен повертати електронні адреси, внутрішні примітки, журнал операцій або службові записи, не потрібні вчителям.

## Що повертає захищений шлюз

Після перевірки HMAC-підпису шлюз повертає:

- учителів, адміністрацію та бібліотекаря без електронних адрес;
- звичайні місця зберігання без службових місць списання/втрат;
- навчальні роки;
- класи в розрізі навчальних років із керівником, кабінетом, датами та станом.

Запит має короткий термін дії, одноразовий nonce і підпис. Повторний або прострочений запит відхиляється.

Дія `applyDraft` у підготовленому коді приймає тільки `academic-year.create`. Вона перевіряє ID таблиці, заголовки аркуша, стан і редакцію чернетки, HMAC, `requestId` та обидва прапорці запису. Повтор того самого `requestId` повертає раніше зафіксований результат замість дублювання рядка. Інші типи чернеток повертають явну помилку «не підтримується».

## Script Property

У налаштуваннях Apps Script потрібно створити Script Property:

```text
SHEETS_GATEWAY_SECRET
SPREADSHEET_ID
LIBRARIAN_WRITES_ENABLED=false
```

Значення має бути випадковим секретом щонайменше з 32 символів. Той самий секрет потрібно зберегти в runtime-змінній Sites `SHEETS_GATEWAY_SECRET`.

Не вставляйте значення секрету:

- у вихідний код;
- у клітинки Google Sheets;
- у документацію;
- у Git-репозиторій;
- у скриншоти або повідомлення.

## Підключення

1. Відкрийте службову Google-таблицю.
2. Оберіть **Розширення → Apps Script**.
3. Переконайтеся, що в проєкті є чинний `PublicCatalogApi.gs`.
4. Створіть файл `LibrarianGateway.gs` і перенесіть до нього однойменний код із цієї папки.
5. У **Налаштуваннях проєкту → Властивості скрипту** додайте `SHEETS_GATEWAY_SECRET`.
6. Для чинного read-only шлюзу нічого не перевидавайте: продуктивну v3 уже перевірено підписаним запитом довідників.
7. Перед майбутнім розгортанням підготовленого маршруту запису створіть резервну копію таблиці та перевірте маніфест: він має містити точний scope `https://www.googleapis.com/auth/spreadsheets` і не повинен містити Drive scope.
8. Нове розгортання вимагатиме повторної авторизації. Створюйте його лише після зелених тестів і залишайте `LIBRARIAN_WRITES_ENABLED=false` в обох середовищах.
9. URL `/exec` залиште тим самим і задайте його у Sites для `PUBLIC_CATALOG_API_URL` та `SHEETS_GATEWAY_URL`.
10. У Sites задайте той самий секрет як `SHEETS_GATEWAY_SECRET`; у Sites та Script Properties залиште `LIBRARIAN_WRITES_ENABLED=false`.

Якщо в історії розгортань уже є версія з іншим номером, не намагайтеся штучно змінити нумерацію. Створіть наступну версію та зафіксуйте фактичний номер у службовому журналі.

## Перевірка після розгортання

Перевіряйте через захищений кабінет, а не вставляючи секрет у URL:

1. Публічний каталог відкривається і завантажує матеріали.
2. Захищений кабінет доступний тільки дозволеному користувачу.
3. Запит довідників повертає вчителів, місця, навчальні роки та класи.
4. У відповіді немає електронних адрес.
5. Службові місця списання/втрат не з’являються серед кабінетів.
6. Запит без підпису, зі старим часом або повторним nonce відхиляється.
7. Після read-only тесту Google Sheets не має жодних змін від шлюзу.
8. Перед першим дозволеним тестом запису використайте копію таблиці; перевірте один `academic-year.create`, повторіть той самий `requestId` і переконайтеся, що другого рядка не створено.

## Безпека

- Вебзастосунок виконується від імені власника таблиці. Підготовлений запис потребує scope `spreadsheets`, тому головними запобіжниками є серверна перевірка виду операції, HMAC, явний ID таблиці та два незалежні прапорці запису.
- Відкритий URL `/exec` не є секретом; захист службового `doPost` забезпечує HMAC-підпис.
- Apps Script не повинен логувати тіло підписаного запиту, секрет або значення інших Script Properties.
- Не додавайте до відповіді аркуш користувачів повністю чи приватні контакти.
- Зміна коду Apps Script не оновлює чинне розгортання автоматично — щоразу створюйте нову версію.
- `LIBRARIAN_WRITES_ENABLED=false` залишається вимкненим у Sites і Apps Script. Не вмикайте обидва прапорці до тесту на копії та окремого рішення бібліотекаря.

## Відновлення

Якщо після оновлення шлюз не працює:

1. Не вмикайте запис до Sheets.
2. У керуванні розгортаннями поверніть вебзастосунок на попередню перевірену версію.
3. Перевірте, що URL `/exec` не змінився.
4. Звірте наявність `SHEETS_GATEWAY_SECRET` у Apps Script і Sites, не розкриваючи значення.
5. За підозри на витік згенеруйте новий секрет і замініть його з обох боків.
6. Повторіть перевірки публічного каталогу й захищених довідників.
7. Якщо відповідь на майбутній запит запису була втрачена, повторіть його з тим самим `requestId`; не створюйте новий ідентифікатор.

Стара інструкція для публічного каталогу збережена у `README_UK.md`; цей файл є актуальним описом двох каналів і захищеного шлюзу.
