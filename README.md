# Сайт бібліотеки Міжнародного ліцею МАУП

Проєкт має два окремі режими:

- публічний каталог для вчителів — лише перегляд;
- захищений кабінет бібліотекаря — підготовка й перевірка службових чернеток.

Google Sheets залишається основною службовою базою. Публічний каталог не записує до таблиці. Кабінет бібліотекаря також не застосовує чернетки до Google Sheets, доки `LIBRARIAN_WRITES_ENABLED=false`.

## Режим учителя

У публічному каталозі реалізовано:

- пошук за назвою, автором та іншими даними картки;
- фільтри за класом, рубрикою, предметом, типом видання і наявністю;
- картки з обкладинкою, кількістю примірників і конкретними місцями зберігання;
- добірки «Останні додані до каталогу», «Для початкової школи», «Іноземні мови», «ЗНО і НМТ»;
- пряме посилання на матеріал у форматі `?material=CAT-0112`;
- копіювання посилання й системне меню «Поділитися» на сумісних пристроях;
- «Повідомити про помилку», що готує текст із CAT-ID та посиланням для надсилання бібліотекарю;
- адаптивне відображення карток і вікна матеріалу на телефоні.

Добірка «Останні додані до каталогу» зараз визначається за порядком CAT-ID, а не за датою надходження. «Повідомити про помилку» не змінює таблицю й не надсилає дані на сервер автоматично: воно відкриває системне меню поширення або копіює підготовлений текст.

Публічна адреса: [https://nazarijshvetz1.github.io/library-site/](https://nazarijshvetz1.github.io/library-site/).

## Захищений режим бібліотекаря

Кабінет бібліотекаря перевіряє користувача та список дозволених облікових записів у runtime-змінній Sites. Службові дії зберігаються в D1 як чернетки, а не як прямі зміни Google Sheets.

Контур чернеток підтримує підготовку даних для:

- нового матеріалу та редагування матеріалу;
- надходження, переміщення, списання і ревізії;
- створення навчального року;
- створення, зміни та закриття класу в конкретному навчальному році;
- переведення класів на наступний навчальний рік.

Чернетка має версію, номер редакції, стан і журнал подій. Це захищає від мовчазного перезапису змін з іншої вкладки. Стан `ready_for_review` означає лише «готово до перевірки».

> Важливо: у вихідному коді підготовлено окремий контрольований маршрут застосування, але він ще не розгорнутий у продуктивному Apps Script. Він підтримує лише `academic-year.create`; усі інші типи чернеток явно відхиляються. Для будь-якого запису обидва незалежні прапорці `LIBRARIAN_WRITES_ENABLED` у Sites та Apps Script мають бути свідомо встановлені в `true`, а `LIBRARIAN_WRITE_MODE` і `SPREADSHEET_ID` мають точно відповідати середовищу. До повторної авторизації та окремого рішення бібліотекаря продуктивні прапорці потрібно залишати `false`.

## ISBN та обкладинка

Для нового матеріалу можна ввести ISBN вручну або відсканувати книжковий EAN-13 камерою. Пошук пропонує бібліографічні дані з Google Books та Open Library, але бібліотекар має звірити назву, автора, видавця, рік та обкладинку з фізичним примірником.

Якщо за ISBN немає потрібної обкладинки, можна:

- вставити HTTPS-посилання на сторінку видання або пряме зображення;
- завантажити приватну фотографію JPG, PNG або WEBP розміром до 8 МБ.

Перед збереженням джерело обкладинки потрібно переглянути й підтвердити прапорцем. Завантажене фото зберігається в приватному R2-сховищі чернеток. Наявність посилання або фото ще не означає, що постійний файл уже створено в репозиторії обкладинок: остаточна обробка й застосування відбуваються окремим контрольованим процесом.

## Навчальні роки та класи

Історія не повинна губитися через щорічне перейменування класів. У чернетках зберігаються окремі записи «клас у навчальному році»: навчальний рік, клас/паралель, керівник, кабінет, дати та стан.

У формі користувач обирає керівника за прізвищем і ім’ям, а кабінет — за зрозумілою назвою або номером. Внутрішні ID зберігаються разом із текстовим знімком значення, щоб історія залишалась читабельною після подальших змін довідника. Закритий клас не потрібно фізично видаляти: він отримує дату закриття і зберігається в історії.

## Дані та інтеграції

- Google Sheets — основні каталогові й службові дані.
- Public Apps Script `doGet` — публічний канал лише для читання каталогу.
- Захищений Apps Script `doPost` — підписані HMAC-запити для службових довідників і багаторівнево захищеного застосування лише нового навчального року.
- D1 binding `DB` — чернетки, їх редакції, стани й журнал подій.
- R2 binding `COVER_UPLOADS` — приватні фотографії обкладинок до опрацювання.
- Sites — захищене розміщення кабінету та runtime-секрети.
- GitHub Pages — статичний публічний каталог із резервним локальним знімком.

Докладний опис роботи й безпеки: [docs/LIBRARIAN_PORTAL_UK.md](docs/LIBRARIAN_PORTAL_UK.md).

Інструкція Apps Script: [apps-script/README.md](apps-script/README.md).

## Локальний запуск і перевірка

Потрібен Node.js 22.18 або новіший.

```powershell
npm run dev:catalog
```

Публічний каталог буде доступний за адресою [http://127.0.0.1:4173](http://127.0.0.1:4173).

Перевірки проєкту:

```powershell
npm test
npm run build:catalog
npm run build:pages
npm run build
```

`npm run build:catalog` готує окремий статичний каталог у `dist-catalog/`, `npm run build:pages` — файли GitHub Pages у `dist-pages/`, а `npm run build` — серверну Sites-версію в `dist/`. Публічна збірка навмисно не пише в `dist/`, щоб її неможливо було помилково розгорнути замість захищеного кабінету.

## Налаштування Sites

У `.openai/hosting.json` зберігаються лише логічні прив’язки:

- D1: `DB`;
- R2: `COVER_UPLOADS`.

Runtime-змінні Sites:

- `LIBRARIAN_ALLOWED_EMAILS` — секретний список дозволених облікових записів;
- `LIBRARIAN_WRITES_ENABLED=false` — обов’язковий безпечний стан до окремого етапу застосування;
- `PUBLIC_CATALOG_API_URL` — HTTPS URL публічного Apps Script `/exec`;
- `SHEETS_GATEWAY_URL` — HTTPS URL того самого розгортання Apps Script `/exec` для захищених POST-запитів;
- `SHEETS_GATEWAY_SECRET` — секрет HMAC, тотожний Script Property з такою самою назвою.

Script Properties Apps Script:

- `SHEETS_GATEWAY_SECRET` — той самий HMAC-секрет;
- `SPREADSHEET_ID` — явний ID службової таблиці;
- `LIBRARIAN_WRITE_MODE` — `copy_test` для повної копії або `production` для основної таблиці; інші значення блокують запис;
- `LIBRARIAN_WRITES_ENABLED=false` — другий незалежний запобіжник запису.

Поточне продуктивне розгортання Apps Script v3 перевірено підписаним запитом читання довідників і залишається безпечним read-only розгортанням. Підготовлений шлюз успішно пройшов окремий тест на повній копії Google Sheets: створення одного року зі статусом `Чернетка`, повтор без дубля, збереження валідації та відхилення некоректного року. Це не вмикає продуктивний запис. Маніфест потребує точного scope `spreadsheets`, тому майбутнє продуктивне розгортання вимагатиме повторної авторизації.

`PublicCatalogApi.gs` поки читає продуктивний ID окремо. У тестовому середовищі на копії змінюється лише захищений `SHEETS_GATEWAY_URL`; публічний `PUBLIC_CATALOG_API_URL` залишається URL продуктивного каналу лише для читання.

Реальні адреси користувачів, токени й секрети не можна додавати до коду, Markdown-файлів, клітинок Google Sheets, журналів або `.openai/hosting.json`.

## Резервне відновлення

- Перед майбутнім увімкненням запису створіть копію Google Sheets і перевірте можливість її відновлення.
- Не видаляйте D1-чернетки або R2-фото під час невдалого розгортання; спочатку поверніть попередню версію Sites.
- Якщо захищений шлюз недоступний, залиште `LIBRARIAN_WRITES_ENABLED=false`: публічний каталог працюватиме з доступного API або перевіреного локального знімка.
- Секрети зберігайте в менеджері паролів. Для ротації створіть новий секрет, оновіть Script Property і Sites runtime, а потім перевірте шлюз.
- Після втрати відповіді під час майбутнього застосування не створюйте новий запит: повторіть операцію з тим самим `requestId`, щоб ідемпотентний журнал не допустив дублювання.
- Жодна аварійна процедура не повинна «догравати» зміни без повторної перевірки бібліотекарем.
